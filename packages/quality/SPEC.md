# Requirement evidence

`spec_checks(ctx)` evaluates each requested requirement against `ctx.shape`. `load_spec(text_or_bytes_or_dict)` validates the safe YAML/data format; it raises `SpecValidationError` for malformed input. Evaluation instead returns explicit diagnostics so a built revision can remain draft. No supplied spec or an empty requirement list is unproven, rather than a failed geometric build.

Duplicate YAML keys and requirement IDs, YAML aliases, ambiguous YAML 1.1 integers (octal/sexagesimal), non-string keys, booleans used as measurements, non-finite values, overflowing unit conversions and malformed ranges are rejected. Text is limited to 1 MiB, 64 nesting levels and 10,000 nodes; dictionary input has the same depth/node limits. Unknown requirement types produce `skip`. Mixed known/unknown fields cannot silently drop the unknown condition. IDs and declared levels are retained; input diagnostics are error-level skips, so malformed specs stay draft.

Lengths default to `spec.units` (`mm` by default or `in`). The geometry's native coordinate unit is `ctx.units`; the engine/export boundary must preserve that convention. Explicit `mm`/`in` suffixes, `nominal ± tolerance`, `{nominal, tolerance}`, and inclusive `{min, max}` bounds are accepted. Exact measurements have a numerical comparison band of 1e-6 in canonical mm, mm² or mm³ (1e-9 for dimensionless values). Explicit tolerance/range boundaries receive no additional band; integer counts remain exact. Dimension powers apply for area/volume. `mass_g` is in grams. Angle values are dimensionless degrees when an angle provider becomes available.

| Requirement | Evidence and limits |
| --- | --- |
| `bbox: {x, y, z}` | Native OCCT optimal bounds, not model parameters, metrics or overridden Python methods. Only requested axes are checked. |
| `solids: n` | Native B-rep solid enumeration. |
| `holes: {count, diameter, pattern: {grid: [pitch_x, pitch_y]}, scope?: all\|cylindrical, through?: boolean}` | Through bores are the default; `through: false` includes open blind bores. End classification rejects sealed voids and through requirements reject dimples. Mirrored analytic surfaces preserve inward orientation. All connected coaxial diameter segments are grouped before diameter filtering, so grooves do not split bores. A count-plus-diameter selects matching bores; an unrelated larger bore is allowed. For default through scope, the Euler characteristic of valid closed analytic shells checks for omitted noncircular tunnels, including tunnels crossing exterior face junctions. Unclassified topology remains unproven. Explicit `cylindrical` limits coverage to recognized full-revolution bores. Grid axes lie in the coordinate plane perpendicular to the common X/Y/Z bore direction; arbitrary oblique grid frames remain unsupported. |
| `clearance: {with: relative.step, min, max}` | Fresh project-contained STEP import, solid-overlap boolean and minimum B-rep distance. Penetration cannot satisfy even zero requested clearance. Traversal, escaping symlinks and non-STEP assets are unsupported. |
| `mass_g: {min, max}` | Native solid volume times a sourced material's nominal `density_g_cm3`; no mass without a named known material. Context/spec material conflicts remain unproven. The material catalog is a separate module. |
| `symmetric: {plane: XY\|XZ\|YZ, tolerance}` | B-rep mirror/symmetric-difference volume is diagnostic only. Even zero volume can hide a subresolution displacement. No certified pointwise or kernel error bound is available, so a potential pass remains skip. A model-to-mirror minimum separation greater than tolerance is a measured disproof and returns fail. |
| `measure: {kind, a, b?}` plus `equals` or `min/max` | S1 semantic resolver, exactly one entity per selector, then its context-bound `entity_shape(ctx, entity)` native geometry. Metadata and indices alone cannot stand in for B-rep geometry. Distance, analytic circle/cylinder/sphere radius, edge/wire length, area and solid volume are supported when the resolver is available. Selector text is never `eval`ed. Angles remain unsupported. |
| `material_at_point: {point: [x,y,z], expected: solid|void}` | B-rep point classification in the declared frame. Boundary points are unknown. This proves one point, not global access or thickness. |
| `min_wall` | A sampled local wall below the required lower bound is a failure witness. Passing samples remain skip: they cannot prove a global minimum wall. |

`process` and `process_settings` are accepted alongside requirements; the process evaluator validates its own declared assumptions. [PROCESS.md](PROCESS.md) describes those screens.

`verification_ready(spec, checks, hard_checks, process=ctx.process)` is a conservative integration helper, not a source of trusted evidence. Pass the context process even when it is absent from the spec. It requires a valid nonempty specification, exact unique per-requirement coverage, matching severity, meaningful measured evidence, a nonempty passing error hard gate and no unproven error results. Spec and process passes with missing or unknown measurements are unproven. A requested process needs matching profile evidence; context/spec conflicts block readiness. Skipped spec requirements and error-level process screens withhold readiness. An explicitly warning-level process screen remains advisory, including when unavailable. This deliberately exceeds the contract's minimum error-level coverage rule; a measured warning may remain advisory. The `process` keyword is required, even when its value is `None`. The caller must bind checks to the actual revision/spec/kernel/artifact and protect evaluation from model code.

The S1 worker trust boundary has independently reproduced counterexamples in [issue #31](https://github.com/justmycode37/AIAD-AI-Aided-Design-/issues/31). S1's containment in [PR #32](https://github.com/justmycode37/AIAD-AI-Aided-Design-/pull/32) now clears worker proof claims and withholds verified status. Reported metrics remain mutable in the interpreter executing model Python. The S5 helper cannot attest that evidence. `evals/quality/probe_worker_evidence.py` deliberately exits nonzero while reported geometry or verified claims disagree with a fresh BREP audit. This is a release blocker, not a sampled agent false-verified-rate estimate.

Run the real-geometry, malformed-input, coverage, process and actual-worker tests using the commands in [README.md](README.md). These tests do not establish that an agent's spec captured the user's complete request. The hidden eval oracle and independent sampled audit must check that gap separately.
