# aad

The `aad` command provides the CLI, local daemon, and MCP adapter for [AAD](../../README.md).

## Runtime packages

The `aad-design` wheel declares these default runtime requirements:

- `aad-engine==0.1.0`
- `aad-quality==0.1.0`
- `aad-drafting==0.1.0`
- `aad-render[vtk]==0.0.1`; its `vtk` extra pins `vtk==9.7.1`

The workspace source mappings keep repository resolution tied to these local packages instead of similarly named registry packages. Built wheel metadata uses normal versioned distribution requirements. A registry install such as `uv tool install aad-design` also requires these component distributions to be available on the configured index; this change does not publish them. The quality package and its on-demand catalog are included in the installed runtime. Optional standard-part construction still requires the quality package's `parts` extra.

## Revision storage

Revision files keep their normal paths under `.aad/revs/<rev>/`. On its first commit after upgrade, a project interns existing revisions; new revisions are interned during commit. Files are hard-linked to matching objects in `.aad/objects/sha256/` and are read-only after commit. `Project.revision_meta()` loads the large `features.json` sidecar in new revisions and still reads older revisions that embed features in `meta.json`. The revision index records which directories have been migrated. Cleanup removes an object only when its hard-link count is one, so no revision or job still points to it.

On 2026-11-05, a scratch project built three times from a read-only copy of `~/AAD/dsg-0b5` revision 7's model and spec. The scratch run used temporary `HOME` and `AAD_HOME`; the source project was not changed. Its original `.aad/` occupied 527 MiB. The scratch revision tree had these logical file sizes and unique inode allocations:

| Revisions | Logical revision files | Unique bytes | Allocated blocks |
|---:|---:|---:|---:|
| 1 | 43.90 MiB | 43.90 MiB | 43.91 MiB |
| 2 | 87.80 MiB | 43.96 MiB | 43.98 MiB |
| 3 | 131.69 MiB | 69.25 MiB | 69.27 MiB |

The second revision reused all large content; the third added 25.3 MiB of new unique bytes despite using the same source. The store shares byte-identical files only. Feature tables are compact sidecars rather than pretty-printed inside `meta.json`, reducing the first scratch revision from the original project's roughly 60 MiB per revision to 43.90 MiB before inter-revision reuse.

## Installed-wheel smoke

Run the local build and isolated install check with:

```bash
uv run --no-project --python 3.12 --script .github/scripts/packaging_smoke.py
```

The helper builds all five workspace wheels, passes the component wheels directly to `uv tool install`, and verifies `direct_url.json` provenance and site-packages imports. It uses temporary tool, home, AAD, and client-config directories and suppresses browser launch. It prints and writes a schema-versioned JSON result to `<work-dir>/packaging-result.json` (or the path supplied with `--result`). The runtime disk measure covers `UV_TOOL_DIR` and `UV_TOOL_BIN_DIR`; it excludes the uv package cache, Python interpreter, and `AAD_HOME` data.

Doctor allows 30 seconds for a valid MCP initialize response and reports the separate one-second reference-Mac target as a performance warning when missed. Packaging retains that warning as a release blocker. Missing or malformed responses fail the functional check. Render/export diagnostics wait up to 130 seconds to cover the workers' 120-second limit and transport cleanup; control calls retain their 15-second limit.

### Measurement on macOS arm64

Measured 2026-11-04 on macOS 25.6.0, CPython 3.12.10. The uv package cache was empty for the fresh-install timing; the host page cache was not flushed or controlled, so this is not a clean-machine benchmark. The full doctor run used a provisioned uv cache.

| Measurement | Result | Target or scope |
|---|---:|---|
| Fresh empty-uv-cache install | 320.606 s | <=180 s; missed |
| Provisioned-cache offline install | 3.770 s | Cached result, not a fresh download |
| Runtime after install | 1,207,504,896 bytes (1.208 GB; 1.125 GiB) | Tool and bin directories |
| Runtime after validation | 1,253,093,376 bytes (1.253 GB; 1.167 GiB) | Includes generated bytecode; <=1,000,000,000 bytes missed |
| Latest prewarm | 118.990 s; completed | build123d first import 45.6 s, second 1.6 s. VTK first 68.6 s, second 1.0 s |
| `aad mcp` first ever start | 1.608 s | Compiles bytecode. Informational, because no host can start it before `aad install` writes the configs |
| `aad mcp` first response after pre-warm | 0.409 s | <1 s; met, with no kernel import |
| Installed `aad doctor --json` | 12.855 s; required checks passed | Real draft part, scene integrity, render, and STL export |
| Installed viewer HTML | 12,996 bytes | Packaged stub viewer |

The 320.606 s install command completed, but that earlier run stopped before the doctor flow, so use it as install timing only.

The doctor warns that the viewer is a stub. The draft build also reports `scene_generation_failed` while retaining the valid BREP; scene integrity, render, and export each pass afterward. Package imports, wheel provenance, and `aad version` were verified from the installed tool. `aad_quality` is absent and was not installed or verified.

The smoke workflow covers `macos-15-intel` and `ubuntu-latest` (both asserted x86_64, with Linux `libosmesa6` and `bubblewrap`). The historical local measurements above cover macOS arm64 before the integration of the quality and scene packages. They do not establish current runtime measurements or release readiness.

## Release blockers

The measured runtime exceeds the 1 GB target and the fresh-cache install exceeds the 3-minute target. VTK is 518 MB of the runtime, so meeting the size target needs a lighter render backend. S3's benchmark in `tests/perf` found ModernGL promising, and it has not replaced VTK. These measurements are not from a clean machine.

## Remote mode

`aad serve --http` serves MCP over Streamable HTTP at `/mcp`, for clients that cannot reach a local process.

```bash
aad serve --add-user alice            # prints a token once; only its hash is stored
aad serve --http --port 8765          # loopback by default
```

- **Authentication:** each request needs `Authorization: Bearer <token>`. The server refuses to start with no users.
- **Isolation:** each user gets a private home under `<AAD_HOME>/users/<name>` and their own daemon, so projects, scenes and config never mix. This is not OS-user separation: all daemons run as the account that started the server, and the worker sandbox is the boundary around model code.
- **Network binding:** a non-loopback `--host` needs `--public-url https://...` with TLS terminated in front of AAD, and needs builds to run in the OS sandbox. Until the engine reports that, the server refuses.
- **In remote mode:** roots are not requested, `aad_show` is always inline, and `aad_import` reads only from the user's own home.
- **Not done:** claude.ai and ChatGPT connectors need OAuth 2.1, which this does not implement. File upload for imports is also not implemented. Neither has been tested with those hosts.
