## Automated evidence

The parent ran the complete locked Python 3.12 drafting suite: **243 passed**,
including export-review regressions for multiline text and directory symlink
substitutions during staging, publication and rollback.
The regressions also cover staged-file substitution, small nonzero dimensions
and rotated sheet annotations.
The 18 golden tests rebuild all 15 drawings, compare their semantic snapshots,
measure every dimension against native OCCT geometry, require no failed drawing
checks, and audit the DXFs. Separate same-machine checks compare repeated SVG,
PDF and PNG bytes for one example from each category. Committed artifact hashes
are recorded in `samples/golden/manifest.json`. Cross-platform comparisons use
geometry and semantic snapshots, rather than assuming identical installed fonts.
Reference generation scopes ezdxf's fixed metadata option to remove changing
timestamps and GUIDs from DXF hashes, restoring the caller's option afterward.
Reference CLASS records are sorted so Python hash randomization cannot reorder
this metadata section.
A subprocess test runs the documented command from the repository root without
`PYTHONPATH` and compares all files from two full generations with different
Python hash seeds byte for byte.

Run from the repository root:

```sh
uv run --locked --package aad-drafting --all-extras python -m pytest packages/drafting/tests
uv run --locked --package aad-drafting --all-extras python packages/drafting/examples/golden_set.py
```

## Visual and independent CAD review

The parent opened and inspected every reference PNG. All 15 DXFs also opened
in LibreCAD 2.2.1.6 arm64 through its independent `dxf2pdf` renderer. The parent
inspected all 15 resulting PDF page images for legibility, view placement,
dimension leaders, table rules, margins and hidden edges. The PDFs, page images
and source DXF hashes are retained in `samples/golden/independent/`.

The standalone application was downloaded from the official LibreCAD release.
Its DMG SHA256 was
`2c5049f5d38346b6152e5b000bb60060f3a2113484bba4bcb388cb690f275879`.
LibreCAD is an external verification tool, not an AAD dependency or a shipped
application. The command used for each sheet was:

```sh
LibreCAD dxf2pdf -a -m -p <width-mm>x<height-mm> -o <review.pdf> <drawing.dxf>
```

This review exposed CAD font substitution crossing table rules, a section label
touching a neighboring view, and an unrecognized custom hidden-line name. The
layout now reserves a larger CAD font envelope and table row spacing; section
labels try positions against emitted geometry and dimensions; DXF hidden edges
use the conventional `HIDDEN` linetype. Failed placement retains the label and
reports a failure instead of omitting it. Text metrics are cached to keep the
layout search bounded in practice.

## Three-sheet human review

The user was shown the PDF sheets for **02 obround panel**, **05 S1 fan-mount
plate**, and **12 grooved spindle**, with the question whether the nominal
geometry could be made from the sheets and what information was missing. The
user's response was: **"Nominal geometry is clear"**.

This records a nominal-geometry review, not a report that parts were fabricated
or that a particular manufacturing process was qualified. No separate reviewer
identity or statement of prior model familiarity was supplied.

The examples deliberately do not invent production requirements. The 2D panel
defines the cut profile; stock thickness and material must be supplied for a
physical panel. All three need applicable dimensional and positional tolerances,
material specifications, edge treatment and finish requirements before production
release. The spindle additionally needs fit, runout, surface finish and any
heat-treatment requirements relevant to its intended use. Those values depend
on the job and cannot be derived from nominal geometry.
