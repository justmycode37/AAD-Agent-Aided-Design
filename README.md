# AAD (Agent-Aided Design)

CAD for agents: a background MCP server that lets any agent design real 2D and 3D parts and prove they meet the request. When the user asks to see a part, the agent shows it inline in the chat.

The Python distribution is `aad-design`; the CLI command and Python modeling import are `aad`. The shorter PyPI name `aad` belongs to another project.

Pre-release and not yet published. [ARCHITECTURE.md](ARCHITECTURE.md) explains how it fits together, and `CONTRACTS.md` is the binding set of interfaces.

## What agents can do

Parts, assemblies with a BOM and interference checks, sheet metal with flat patterns, surfaces, direct edits, threads, gears and standard parts, 2D sheets, drawings, and STEP, IGES, STL, OBJ, PLY, 3MF, GLB, DXF, SVG and PDF exchange. [`docs/cad-parity.md`](docs/cad-parity.md) compares this with commercial CAD, including what is still missing. Agents read the guide, playbook `aad.guide.v1`, through `aad_library`, with working code in `workflow.capabilities.v1`. `aad install` also adds the guide as the `aad` skill for Claude Code.

## Develop

Requires Python 3.12 and [uv](https://docs.astral.sh/uv/) (`brew install uv`).

```bash
uv sync --all-packages              # create .venv with every workspace package
uv run aad version                 # run the CLI from the workspace
uv run pytest packages/platform     # one package's tests
uv run pytest tests/e2e             # end-to-end smoke test
```

A new package needs only `packages/<name>/pyproject.toml`; the root workspace picks it up. After changing dependencies, run `uv lock` and commit `uv.lock`.

The chat viewer gives users simple controls and an agent-curated Views menu.
Agents provide interior, section, component, camera, and sourced analysis recipes
through `aad_show.views`. The local CAD window retains the native inspection
tools. Agents should read the [AAD guide](skills/aad/SKILL.md), which covers every tool and current limits, and the [viewing skill](skills/aad-viewing/SKILL.md).
See [CAD viewing controls](docs/cad-viewing.md) and [HTML chat exports](docs/html-viewer.md).
To change the viewer, run `npm ci`, `npm run build`, `npm test`, and
`npm run test:e2e` in `viewer/`; commit the packaged HTML generated by the build.

Pull requests run CI on Linux. Pushes to `main` also run on macOS Intel (`macos-15-intel`), so a Mac-only failure can appear after merging. A newer push cancels the older run on the same branch. Hosted arm64 jobs exhausted runner capacity (issue #60); local macOS arm64 smoke results remain separate evidence. Every PR runs the smoke test. Documentation skips package tests; platform and viewer changes run their own tests. Shared CAD, root config and CI changes run all package tests, as does `main`.

Selected package tests also run with the complete installed workspace alongside the smoke tests, so consumer conflicts cannot hide behind package isolation. Offline benchmark harness, SDK, statistics and native corpus controls run separately. Installed-wheel checks include all five runtime packages and the on-demand library.
